Fix: ignore gaps when calculating consensus sequence

Fixed critical bug in consensus_sequence.py where gap characters ('-') were
being counted when determining the most common character at each position.
This caused incorrect consensus sequences with spurious gaps appearing where
positions had gaps as the most frequent character.

Changes made:
- Added gap filtering: `if char != '-':` before counting characters
- Added fallback to 'X' for positions that are all gaps (representing unknown amino acid)
- Tested successfully with msa_output.fasta

The fix ensures biologically meaningful consensus sequences. Gap characters
represent alignment artifacts and should not be included in consensus calculation.
Using 'X' for all-gap positions follows standard bioinformatics practice for
representing ambiguous or unknown amino acids.

Bug discovered during first test run when examining the consensus output, which
contained many '-' characters that don't make biological sense in a consensus
sequence. This is a common mistake in sequence analysis code and represents
the natural debugging cycle in bioinformatics programming.

Verified by: Tested with msa_output.fasta and confirmed consensus sequence
contains only valid amino acid characters without spurious gaps.
